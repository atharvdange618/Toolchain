## Design

### Experience

1. On a terminal, show a loading indicator for real waits: resolving dependency versions, running a noninteractive scaffolder, installing dependencies, Husky, and lint/format subprocesses.
2. A successful task leaves one completion line. Keep the existing compact file summaries and final Next steps box.
3. Use one Clack spinner per active task. Its message may show the latest useful child-output line. Do not run two cursor-owning displays, such as a spinner and task log, at the same time.
4. Preserve warnings from both child streams. On success, print up to 20 warning/deprecation lines; if there are more, print the count and a path to the complete log. Preserve stderr diagnostics conservatively instead of assuming every stderr line is an error.
5. On failure, print the last 40 diagnostic lines and a path to the complete log before the command's existing manual-retry message. Ordinary noninteractive/redirected runs retain streaming stdout/stderr and do not animate or rewrite the terminal.
6. External tools that may ask questions inherit the terminal and get a static heading, never captured output. Keep interactive Next.js questions when the user did not pass `--yes`.
7. Toolchain already chooses React TypeScript. Run create-vite with `--template react-ts --no-immediate --no-interactive` even when the outer template selection was interactive. Verify those flags against the actual installed/latest scaffolder before changing its tests; do not silently choose new Next.js options.

### What stays outside this change

- No Ink, full-screen interface, doctor navigation menus, new CLI flags, new package manager, or dependency concurrency scheduler.
- Doctor stays a fast synchronous check. Do not add an artificial wait or spinner to make it look busy.
- No animation around synchronous disk writes. Keep writes and manifest recovery ordered as they are today.
- No changes to dependency selection policy, generated bytes, required packages, TypeScript pin, configuration preservation, or update conflict decisions.
- Do not run arbitrary package lifecycle scripts in a captured no-input mode if they require user input. Existing inherited behavior remains the fallback for a known interactive phase.

## Constraints

- Node >=20.12.0; no APIs available only in newer Node versions.
- Strict TypeScript, no `any`; narrow child-process errors and parsed registry JSON from `unknown`.
- Progress rendering requires both stdin and stdout TTYs and a non-CI environment. CI or redirection uses static output and preserves stream destinations.
- Install, Husky, Git, lint and format commands stay sequential. Registry lookups run concurrently (`Promise.all` over the requested names): each `npm view` takes about 1.8s, so nine sequential lookups cost about 16s on init, which is the wait the spinner exists for. Finish prompts and resolve required versions before writes, just as update does now.
- `doctor --json` remains exactly one JSON document on stdout; errors stay on stderr. Doctor must not spawn a child, open progress logs, or query the registry.
- Version lookup failure or cancellation before writes must leave the project untouched. Keep the stable-release age policy, successful-result cache, selective update lookups, and TypeScript `^7.0.2` offline.
- Update still writes its applied-content manifest after an install fails. Rerunning update still does not retry an install for already-declared dependencies; keep the explicit retry instructions.
- Ctrl+C must stop the owned child process tree and end progress, not merely hide a widget. No later phase or success message may run after cancellation. Do not kill unrelated processes.
- Cancellation after update has written package.json must follow the same manifest-save/manual-install recovery as install failure. A second SIGINT during that recovery prints the manual-install line and calls `process.exit(130)`; it does not wait for the manifest save. Do not claim rollback.
- Clack 1.9.0's `spinner()` adds its own SIGINT/SIGTERM listeners while it runs (`dist/index.mjs`), and its handler only stops the widget. Any SIGINT listener disables Node's default exit, so a spinner alone would let Ctrl+C stop the animation while the CLI keeps going. Every spinner gets the command's shared `AbortController.signal` through its `signal` option, and its `onCancel` aborts that same controller, so Clack and the runner share one cancellation path.
- Existing commit rules apply: only commit when asked, and run lint, typecheck and tests before every requested commit. No automatic merging of issue #11.

Use these boundaries; do not expose the widgets to generators:

```ts
interface CommandOptions {
  cwd: string;
  mode: 'inherit' | 'stream' | 'capture';
  signal?: AbortSignal;
  onOutput?: (text: string, stream: 'stdout' | 'stderr') => void;
}

runCommand(command: string, options: CommandOptions): Promise<{ stdout: string }>;

interface TaskOptions {
  cwd: string;
  title: string;
  successMessage: string;
  interactive?: boolean;
  signal?: AbortSignal;
}

runTask(command: string, options: TaskOptions): Promise<void>;
withProgress<T>(title: string, work: (signal: AbortSignal) => Promise<T>): Promise<T>;
```

`runCommand` takes existing internally constructed command strings, not arbitrary user input. Continue validating project names/package managers before construction. Use asynchronous `spawn` with the platform shell for these existing shell commands so Windows `.cmd` shims still work. Do not add a shell-command parser. Pass `cwd` as an option; never interpolate directory paths into the command.

`inherit` keeps child stdio. `stream` emits both streams through callbacks without accumulating their full content. `capture` returns only stdout, bounded at 1 MiB; exceeding the bound rejects rather than parsing truncated registry JSON. Keep stdout and stderr separate. Wait for `close`, not only `exit`, so the last diagnostics are consumed. Reject once on launch error, nonzero exit, signal or abort.

For `stream` and `capture`, child stdin is ignored, not left as an unwritten pipe. An unexpected child prompt must fail with the existing manual-retry instruction rather than wait invisibly; never automatically retry an install and repeat its lifecycle scripts. `inherit` is the only mode allowed for known interactive phases.

Before writing the tail/collapse logic, try Clack's `taskLog` (`limit`, `retainLog`, `showLog`): it already clears on success and keeps output on failure. It still needs the temporary log and the warning filter, since it drops warnings on success. Use it if it covers the 40-line tail; otherwise ledger why not.

Expect `git init` to print `hint:` lines on stderr when `init.defaultBranch` is unset. Under the every-stderr-line rule they show as diagnostics; that is acceptable, not a bug.

For terminal tasks, write complete output to a unique temporary log using streams, not an unbounded in-memory array. Keep a 40-line tail and at most 20 displayed warning lines; limit any incomplete UI line to 16 KiB so newline-free output cannot grow indefinitely. UTF-8 decoding must survive split multibyte characters. Treat carriage-return progress as replaceable lines for display, preserving raw logs. Clean successful logs when no diagnostics need keeping; retain and print their paths on failure or omitted diagnostics. Close log streams and remove listeners on every outcome.

Treat every nonblank stderr line as a diagnostic worth preserving. Also preserve stdout lines matching the case-insensitive whole words `warn`, `warning`, or `deprecated`; this covers the observed npm and pnpm warnings. Strip terminal control sequences for display and classification using Node's built-in utility, while keeping raw logs intact. After 20 displayed diagnostic lines, report how many were omitted and the log path.

Define a narrow cancellation error/predicate in `process.ts`, shared by command callers. Never treat cancellation as an ordinary recoverable lint failure and continue to format. Use the runner's tracked PID/process group for cleanup. On Windows, terminate only its owned tree with `taskkill /pid <pid> /T /F` (Node has no built-in tree kill). On POSIX, `stream` and `capture` children start with `detached: true` and are stopped with `process.kill(-pid, signal)`. `inherit` children are never detached: a background process group that reads the TTY gets SIGTTIN and stops, which would freeze create-next-app's questions. They stay in the terminal's foreground group, where the terminal's own Ctrl+C already reaches them, and cleanup signals only their PID. A shell's exit alone does not prove its children stopped. Set `windowsHide: true` for background captured children.

While a runner-owned command is active, bridge SIGINT/SIGTERM to that command's cancellation path even if the caller supplied no AbortSignal. Remove only those listeners on completion. Respect Clack's already-cancelled spinner state so cleanup does not print a second failure/completion. Registry lookup catch blocks must rethrow the typed cancellation instead of converting it to a network failure or caching it. Test both a passed AbortSignal and an actual signal to a fixture CLI process.
