# v2.0.0: replace ESLint with oxlint

Status: done. Steps 0 to 9 landed from 2026-10-30 to 2026-11-10. 2.0.0 and 2.0.1 published 2026-11-10; 2.1.0 followed the same day with Expo support, the stack refusals, `.gitattributes` and the no-TypeScript warning. This file stays as the historical record; later changes are in `CHANGELOG.md`. Written 2026-10-30 against v1.5.0.

## Why

- `typescript-eslint@8.72.1` peers on `typescript >=4.8.4 <6.1.0`, so v1 pins `typescript@~6.0.3` while `typescript@latest` is 7.0.2. Every repo this tool sets up starts a major behind.
- Oxlint type-aware linting (`oxlint-tsgolint`) runs on TypeScript 7 and covers 59 of typescript-eslint's 61 type-aware rules.
- Oxlint 1.90.0 has every plugin v1 uses built in, except `perfectionist` and `react-you-might-not-need-an-effect` (see Gaps). One package, one version, so the eslint peer-group resolver in `src/utils/versions.ts` goes away.
- Estimate, not measured: pre-commit lint drops from roughly 10 to 30 s (type-aware ESLint, medium repo) to 1 to 2 s. Step 7 measures it.

## Decisions

| Area            | v2 choice                                                                           |
| --------------- | ----------------------------------------------------------------------------------- |
| Linter          | `oxlint` + `oxlint-tsgolint`, config in `.oxlintrc.json`                            |
| TypeScript      | `^7`, replacing `~6.0.3`                                                            |
| Formatter       | Prettier stays. Revisit `oxfmt` (0.75.0 today) once it reaches 1.0                  |
| Hooks           | Husky + lint-staged + commitlint + commitizen, unchanged                            |
| Pre-commit      | lint-staged, typecheck, and **new**: tests, if a `test` script exists               |
| ESLint fallback | None. One linter, one code path. Revisit only if a real repo needs a missing plugin |

## Gaps and risks

- **perfectionist, react-you-might-not-need-an-effect**: dropped (all-native, no alpha JS plugins). The changelog must say so.
- **TS 7 dropped tsconfig options** (e.g. `baseUrl`): `src/generators/tsconfig.ts` must not emit them. Repos upgrading from v1 may need manual tsconfig fixes, so the changelog should list these.
- **Monorepos**: type-aware lint needs workspace packages built (their `.d.ts` must exist). The `turbo` and `pnpm-monorepo` templates need lint to run after build, or with type-aware off for unbuilt packages.
- **typecheck script**: confirm `tsc --noEmit` and `tsc -b` behave the same under TypeScript 7 (the project-references handling in `package-json.ts` relies on that).
